# Truebex SEO & growth

Pair with `truebex-brand-voice` (what to say). This skill covers how pages get
found, shared, and indexed fast. Be honest with the user: no technique
guarantees "viral"; what reliably works is crawlable pages, a real answer to
real searches, share-ready previews, and repeated distribution.

## How the site is wired (don't break these)

- Static export (`next.config.ts` `output: "export"`, `trailingSlash: true`) on GitHub Pages, so every URL ends in `/`.
- Global metadata + Organization/WebSite JSON-LD: `src/app/layout.tsx`.
- Home JSON-LD (SoftwareApplication + FAQPage): `src/app/page.tsx`, built from `FAQS`/`FEATURES` in `src/lib/constants.ts` so the markup always matches the visible text.
- `src/app/sitemap.ts`, `robots.ts`, `manifest.ts` (all `force-static`). **Add every new public page to the sitemap.** Dashboard/login are `noindex` and disallowed.
- Social card: `public/images/og-image.jpg` (1200×630), generated by `scripts/make_web_assets.py`.
- Icons: `src/app/icon.svg`, `apple-icon.png`, `favicon.ico`, `public/icon-192/512.png`.

## Per-page checklist (every public page)

1. `export const metadata` with a unique `title` (≤ 60 chars incl. " · Truebex"), `description` (140–160 chars, contains the page's main phrase and a benefit), `alternates.canonical` with trailing slash.
2. Exactly one `<h1>`, containing the main phrase. H2s for each sub-topic (they become sitelinks/snippets).
3. Server-rendered text: content must be in the HTML, not fetched client-side. Client components are fine for interaction; keep copy in props/constants.
4. Every image: `alt` that names what's shown + the feature; explicit `width`/`height`; `loading="lazy"` below the fold.
5. Internal links: link to the page from the nav/footer or a related section, and link out from it to signup/demo.
6. Structured data where it fits: `FAQPage` (Q&A), `TechArticle` (docs), `SoftwareApplication` (product), `HowTo` (step guides), `BreadcrumbList` for nested pages.
7. Add to `sitemap.ts`. Build and check `out/<page>/index.html` contains the title, description, canonical and JSON-LD.
8. Performance: no full-screen hidden images, no `priority` on below-the-fold media, keep JS per page lean (Lighthouse ≥ 90 on mobile is the target).

## Get indexed fast (do once, then on every launch)

- Google Search Console: verify `truebex.com` (DNS TXT at Cloudflare), submit `https://truebex.com/sitemap.xml`, use URL Inspection → Request indexing for new pages.
- Bing Webmaster Tools: import from Search Console (also feeds DuckDuckGo/ChatGPT search); enable IndexNow.
- Check `https://truebex.com/robots.txt` and the sitemap load after each deploy.

## Distribution playbook (where views actually come from)

Short real captures of the app outperform any copy. For each feature, cut a
10–20 s clip (draw a wall → light updates → walk in) and post it natively:

- **X / LinkedIn / Instagram Reels / TikTok / YouTube Shorts** — same clip, platform-native caption, one line + link. Architects live on LinkedIn and Instagram; Unreal devs on X and YouTube.
- **Reddit** — r/unrealengine (tech angle: "Lumen CAD tool, drag cost 240→4.3 ms"), r/architecture, r/Revit, r/InteriorDesign. Post as a builder sharing work, not an ad; answer every comment.
- **Unreal forums / Epic showcase**, **ArchDaily / Archinect** product listings, **Product Hunt** launch day (prepare: OG card, 4 captures, first comment with story).
- Every share uses a page URL with a matching OG card — test previews with the LinkedIn Post Inspector and X card validator.
- Ask early users for a 1-line quote + capture; add them as testimonials (with permission) — social proof converts the traffic.

## Measure

Add privacy-friendly analytics (Plausible/Umami/Cloudflare Web Analytics —
Cloudflare is already in front of the domain) before any launch push; track
signups and demo requests as goals. Review Search Console queries monthly and
write the next page for the best-performing query cluster.
