Developers

The Truebex MCP server

Your AI app starts the server on your computer and talks to it over stdio. The server passes each tool call to the Truebex app you have open, through a private pipe only your Windows user can reach. Truebex asks before each kind of action, makes every edit one undo step and lists every call.

On the roadmap. The Agent panel, where you turn connections on, arrives in a coming Truebex release. Until then every tool call answers app_not_running.

Allow connections in Truebex

  1. In Truebex, open Tools > AI > Agent and turn on Allow AI apps to connect. It is off by default and stays on until you turn it off. While it is off, no AI app can reach Truebex.
  2. The first time your AI app calls a tool, Truebex asks what it may do with the open project: read, read + edit, or read + edit + export. You can also deny. Truebex waits up to 30 s for your answer.
  3. Your answer lasts for that connection only, never for an app by name. Change or revoke it in the Agent panel at any time; the next connection asks again.

Install

Claude Desktop

In the Agent panel, click Install in Claude Desktop, or open truebex.mcpb in the Truebex install folder: Claude Desktop shows its install dialog and brings its own Node. Or add this entry to claude_desktop_config.json (Settings > Developer > Edit Config) and restart Claude Desktop.

{
  "mcpServers": {
    "truebex": {
      "command": "node",
      "args": ["<install>\\MultiWindow\\Tools\\mcp\\truebex-mcp.mjs"]
    }
  }
}

Claude Code

Needs Node 20 or newer. Add it once for your user; /mcp then lists truebex with its 21 tools and three resources.

claude mcp add --scope user truebex -- node "<install>\MultiWindow\Tools\mcp\truebex-mcp.mjs"

Any MCP client

Configure a stdio server with the command node and this argument; the Agent panel shows the exact path. Revisions 2026-07-28, 2025-11-25 and 2025-06-18; tools and resources.

<install>\MultiWindow\Tools\mcp\truebex-mcp.mjs

Rolling out: @truebex/mcp is being published to npm.

Several Truebex windows

The server talks to the newest running Truebex, a released build before a development one. To pin one, set TRUEBEX_AGENT_PIPE and TRUEBEX_AGENT_TOKEN in the server's entry: %LOCALAPPDATA%\Truebex\agent\instances lists each running app's pipe and token.

create_layoutCreate a layout from a brief

Lay out a flat or a house on a plot from a ROOM PROGRAM (room types, target areas in m2, which rooms open onto which) as ordinary walls, rooms (spaces with names and types), doors and windows. A seeded engine makes several candidate plans and checks each one against sanity limits (minimum room areas and widths, door and corridor widths, a window in every habitable room, every room reachable from the entrance; a UK or a US set) -- never a code-compliance claim. Without choose NOTHING changes: the candidates come back with their scores and failures (in the Truebex assistant the best valid ones are shown to the person as cards). Call again with the same arguments and choose (-1 = the best valid) to draw one as ONE undo step. A failed check comes back as an error carrying the report: repair the program and call again (at most 3 repairs, then the skill stops). The same program and seed always give the same plans. Areas in m2, lengths in mm.

Resources

AI apps that read resources get the same data without a tool call. Reading one needs the read class; the server lists them even while Truebex is closed.

URIWhat it holds
truebex://state/digestWhat Truebex shows now, as the read_state digest (plain text).
truebex://project/summaryThe open project: its name, storeys, rooms and counts (JSON).

What it never does

  • It never sees a Truebex sign-in, an API key or your AI account's credentials; it talks only to Truebex on your computer.
  • It cannot quit Truebex, delete or overwrite a project or library file, write outside the project's export folder, run console commands or drive the interface.
  • It cannot change settings, with one exception: a tunable, which set_tunable sets by name. A tunable is typed and range-checked, a Design tunable (one that changes the picture or the drawing) is one undo step, and setting one is never a console command.
  • The creation tools (create_layout, create_theme, create_fills, create_object, create_material and write_sheet_text) take what you want as data, such as a room program, and Truebex makes the result itself. Called without choose, a creation tool changes nothing and returns checked candidates; called again with choose (-1 for the best), it applies one of them as one undo step. create_theme, create_object and create_material also keep what they make in your library.
  • Their checks are sanity rules (for a layout: minimum room areas and widths, door and corridor widths, a window in every habitable room, every room reachable), never a building-code check: no result claims compliance. A failed check returns its report, so your AI app can repair the request at most 3 times; then the tool stops.
  • The remove tool deletes only what this connection created. Anything else, your own walls or another connection's work, is refused and nothing is removed.
  • set_properties sets the code, name and type of rooms (a room's code is its number, such as G.01), the code and name of storeys, and the name of doors and windows, in batches of up to 200 as one undo step. It never applies part of a batch: every item applies, or nothing changes. It is one of the edits that may also travel in the project log.
  • Every call is listed in the Agent panel and in a daily audit file kept 30 days. Every edit to the project is one undo step, and undo takes back only the AI app's own steps.
  • Text from the project, such as room names and notes, reaches your AI app as data, never as instructions.
