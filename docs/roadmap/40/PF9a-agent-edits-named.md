## Goal

When an agent's edit wins — the assistant, or someone's script or connected assistant using an API key through
`/v1` — the person whose edit was replaced reads that an agent made it, on the web app and on the Android app, in
the conflict line, in the history and in the phone's notification. A member is still named, the person's own other
device still reads "You changed this first on another device", and a person the app cannot name still reads
"Someone".

## Design

**API:** none. **Data:** none on the server. On the web, `Winner.author_kind` is optional in IndexedDB (a winner
stored before PF9a reads as a person); on Android `Winner.authorKind` rides in the outbox row's `winning` JSON (no
migration) and `HistoryItem.authorKind` comes from the `ops` table's existing `author_kind` column.

**The rule** (the same in both clients): an operation with `author_kind` `agent` is named by the agent label,
whatever its author id (contract §6.2: an agent session id or a key's own, never a member's); otherwise the
person's own author id gets the self text, a member's author id their name, anything else "Someone". The agent test
comes first, so an agent's edit is never "you" (`HistoryItem.mine` is false for an agent's operation).

* Web: `src/viewer/outbox.ts` — `AuthorKind`, `Winner.author_kind`, `WireOp.author_kind` (required, as
  `openapi/clients.json` says), `ConflictText` and the pure `conflictLine()`; `EditsList` in
  `src/components/app/ProjectPanels.tsx` builds the texts from `APP` and calls it.
* Android: `lib/replica/replica.dart` — `agentKind`, the pure `authorName()`, `HistoryItem.authorKind`;
  `lib/sync/sync_engine.dart` — `ConflictText.agent` and `ConflictText.line()` (the notification and the edit list);
  `lib/screens/panels.dart` — the history's `who()` through `authorName()`; `lib/services.dart` — `agent:
  s.agentAuthor`.

**UI copy:** `APP.agentAuthor` and `agentAuthor` in `app_en.arb`: "An assistant or script". Chosen with the brand
voice: plain words, no product named, true for both kinds of agent — the in-app assistant (and a person's own
assistant through the MCP package) and a script using an API key. Rejected: "Someone" (the bug), "An assistant"
(untrue for a plain script), "An automated edit" (reads "An automated edit changed this first — your edit was
replaced": two edits in one line), "An agent" (reads as a person's agent), "API key" (developer jargon in a phone
notification).

**Security and privacy:** nothing new is read or sent; the label names no person.

## Human test

As T34's live run. Three terminals in the worktree.

1. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\try-mobile.ps1 -Reset` → the API on :8000, a render
   worker, the House, and `out/` built against the local API (a few minutes); it prints the project id and Sam's
   device token (`tbx_dev_…`) and keeps running.
2. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\autopilot-serve.ps1` → it prints the site address.
   Open `/dashboard/keys/` there, sign in as `alex@example.com` / `password123`, make a key with `projects:write`
   ticked → a key starting `tbx_live_` (copy it).
3. Phone: start the emulator or connect a phone, then `powershell -NoProfile -ExecutionPolicy Bypass -File
   scripts\try-android.ps1` → the app opens; sign in as Alex; open House.
4. Phone offline: airplane mode on **and** Ctrl+C in the try-android window. House → Rooms → Oslo 3-seater sofa →
   Edit → Away → "Waiting for connection". Close the app (home, swipe it away).
5. `cd server; .venv\Scripts\python.exe scripts\demo_mobile.py --token tbx_live_… move --project <id> --entity Oslo`
   → "Move Oslo 3-seater sofa: accepted as …".
6. Reconnect: `scripts\try-android.ps1 -RelayOnly`, airplane mode off → within a minute (WorkManager) the
   notification "Edit replaced · House — Move Oslo 3-seater sofa: Away 250 mm: **An assistant or script changed this
   first — your edit was replaced**". Open House → History: that line at the top with Dismiss, and the key's
   operation listed as "Move Oslo 3-seater sofa · An assistant or script · …".
7. Browser: open the site's `/app/`, open House, DevTools → Network → Offline; Rooms → Oslo 3-seater sofa → Away;
   run step 5's command again; Network → No throttling → under "Your edits" the move reads "**An assistant or script
   changed this first — your edit was replaced**".
8. Control: repeat step 4 (or 7) and run step 5 with Sam's `tbx_dev_…` token instead → "**Sam** changed this first —
   your edit was replaced", and History lists Sam's operation as "Sam". Nowhere "Someone".

## Risks / traps

* `adb reverse` ignores airplane mode: the phone is offline only with the relay stopped too (PF10 deviation 9).
* `try-mobile.ps1 -NoBuild` keeps `out/` as it is: after the verify gate, `out/` points at the production API, so
  the browser steps need the build (step 1 without `-NoBuild`).
* The generated `app_localizations*.dart` must come from `flutter gen-l10n` (or `flutter pub get`), never by hand;
  the pytest checks the ARB and the generated getter agree.
* A winner stored before this change has no `author_kind` and reads as a person (name or "Someone"); nothing is
  migrated.
